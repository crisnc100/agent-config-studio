**I would block implementation on the cleanup safety gaps.** The plan contains a destructive index-edit rule, relies on trash behavior that can overwrite backups, and misreads Git worktree metadata. These findings come from read-only inspection; I changed nothing.

1. **Critical — Removing an index “line” deletes unrelated memories’ links.**  
   The plan explicitly proposes removing whole lines, and its acceptance test reinforces that behavior ([plan.md:76](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:76), [plan.md:140](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:140)). Real Kylie data disproves the assumed one-memory-per-line format: [MEMORY.md:73](/Users/cortega/.claude/projects/-Users-cortega-Documents-Garman-Homes-05-Development-kylie-kylie-main/memory/MEMORY.md:73) contains **13 links, five dangling and eight valid**. Removing that line to repair one missing target removes eight valid references. The bar must preserve unrelated links and prose on the same line, including when several selected findings touch that line.

2. **Critical — Existing trash IDs collide and can destroy earlier backups.**  
   Trash IDs combine a timestamp with **second precision** and the basename. The destination directory is reused, then `rename` writes into it ([mutate.js:170](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/mutate.js:170), [mutate.js:249](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/mutate.js:249)). Two same-named files trashed within one second can share a destination; on this platform, renaming a file over an existing file replaces it. Metadata is then overwritten too. Duplicate cleanup and repeated `MEMORY.md` backups make this especially relevant. “Never overwrites” needs a simultaneous same-basename test, not just an existing-live-destination test.

3. **High — “Every cleanup is restorable” has no operation-level implementation contract.**  
   Trashing a fact also edits its index, but existing restore restores **one original path** and removes its trash entry ([plan.md:87](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:87), [mutate.js:209](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/mutate.js:209)). Restoring the fact therefore does not restore its index reference. Index-only repairs, newly created indexes, orphan migrations, and duplicate decisions have still different undo requirements. The bar lacks complete-operation restore, restart recovery, and restore after an agent has subsequently edited the index. A byte-identical file round trip does not establish any of these.

4. **High — An mtime check does not protect the complete change.**  
   “The target’s mtime” is undefined for actions touching a fact, two indexes, directories, and destinations ([plan.md:111](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:111)). A child file appearing inside `memory/` need not change the parent slug directory’s mtime. Another request can change an index after validation. Restore also checks existence separately from renaming, leaving a window in which a newly created destination can be overwritten ([mutate.js:215](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/mutate.js:215)). Missing tests include concurrent Accepts, duplicate submissions, changes to every participating file, destination creation during execution, and emptiness changing after preview.

5. **High — Failure during trashing can leave no usable ACS recovery entry.**  
   Existing deletion moves data **before** writing trash metadata; malformed or absent metadata makes the item invisible to `listTrash`. History failures are swallowed ([mutate.js:164](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/mutate.js:164), [mutate.js:181](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/mutate.js:181), [mutate.js:202](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/mutate.js:202)). The cross-device fallback copies and then recursively removes the source, without checking for intervening source changes. The plan needs a defined outcome for disk-full, permission, history, metadata-write, copy, and process-interruption failures. Happy-path restore tests miss this entirely.

6. **High — The Git worktree premise is factually wrong.**  
   The plan says worktree `.git` files name the common directory ([plan.md:50](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:50)). The inspected [.git:1](/Users/cortega/Documents/Projects/personal/airflo-wt/airflo-run-planner-cleanup/.git:1) instead names `AirFlo/.git/worktrees/airflo-run-planner-cleanup`. Its separate [commondir:1](/Users/cortega/Documents/Projects/personal/AirFlo/.git/worktrees/airflo-run-planner-cleanup/commondir:1) contains `../..`. Following only `.git` fragments one repository into separate groups. Fixtures must represent this actual two-step resolution, relative gitdir paths, and project directories below a checkout root. Also, `.git` is denied by the current general path resolver ([paths.js:31](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/paths.js:31)); the internal metadata-reading boundary is unspecified.

7. **High — Failed slug resolution is not evidence that memory is orphaned.**  
   The plan acknowledges lossy encoding but specifies greedy resolution, then proposes relocation or trash based on a normalized last segment ([plan.md:22](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:22), [plan.md:71](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:71)). Multiple existing paths can encode identically; inaccessible paths and missing mounts can look absent; an unrelated repo can be the only basename match. For an unresolved slug, even the original last segment may be unknowable. The acceptance fixtures do not distinguish ambiguous, inaccessible, non-Git, relocated, and confirmed-missing scopes. An explicit Accept does not make a misleading “orphan” classification safe.

8. **High — Orphan migration specifies filename collisions but not reference migration.**  
   Both the old and current AirFlo memory directories contain their own `MEMORY.md`. “Keep both with a suffix” cannot sensibly settle that index collision by itself ([plan.md:74](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:74)). If `foo.md` becomes `foo-2.md`, source index links still name `foo.md` unless explicitly rewritten. The plan omits destination-index integration, relative links inside bodies, partial moves with skipped files, retained archives/non-Markdown files, and undo of the combined migration. Files can survive byte-identically while their discoverability or references break.

9. **High — Server-issued IDs do not establish filesystem safety.**  
   Current registry IDs are simply base64url-encoded paths ([registry.js:8](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/registry.js:8)). Discovery follows symlinks and reads directories without establishing containment at each step ([registry.js:176](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/registry.js:176)); `resolveSafe` returns the symlink’s target, so passing a memory alias into deletion can delete the target ([paths.js:48](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/paths.js:48)). Tests posting literal `../` miss forged encoded IDs, valid-but-ineligible IDs, symlinked directories, denied targets behind innocent `.md` names, and link replacement after preview. The existing same-origin gate is real ([server.js:850](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/server.js:850)); it does not solve these filesystem authorization problems.

10. **High — The empty-directory target counts confuse empty memory with deletable scope.**  
    My read-only enumeration found **241 empty `memory/` directories, but only five parent slugs containing nothing except that directory**. The other 236 contain additional entries. An inspected temp probe contains an empty memory directory **and a transcript**. Consequently, the deletion condition at [plan.md:69](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:69) cannot deliver the implied bulk cleanup population at [plan.md:132](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:132). Eligibility counts must be separate from findings; otherwise the discrepancy invites broadening deletion to transcript-bearing slugs.

11. **Medium — `tool_use` proves an attempted write, not a completed write.**  
    Real records nest tools under `message.content[]`, with `input.file_path`; completion arrives separately through `tool_result.tool_use_id`. I inspected both [Write at transcript line 538](/Users/cortega/.claude/projects/-Users-cortega-Documents-Projects-personal-AirFlo/53191854-b2ba-40d0-bb0e-96ed40a7de62.jsonl:538) and [Edit at line 543](/Users/cortega/.claude/projects/-Users-cortega-Documents-Projects-personal-AirFlo/53191854-b2ba-40d0-bb0e-96ed40a7de62.jsonl:543), plus a [memory Write at line 3307](/Users/cortega/.claude/projects/-Users-cortega-Documents-Projects-personal-AirFlo/8d6ce148-ff7f-49d7-b476-552cb82e361b.jsonl:3307). Counting calls alone labels failed or interrupted operations “last written” ([plan.md:58](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:58)). Missing cases include error results, missing results, nested subagent transcripts—which exist here—partial JSONL tails, and writes originating outside the grouped repo’s sessions. Absence of retained evidence must remain “unknown.”

12. **Medium — Indexes, archives, and review state have contradictory or missing semantics.**  
    “Each memory `.md`” includes `MEMORY.md` itself; the current discovery includes it too ([plan.md:56](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:56), [registry.js:212](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/registry.js:212)). Without an explicit exclusion, the index can become an unindexed fact or a trash candidate. Archived files can be accidentally reintroduced by the unindexed repair. “Keep” persists a date but never specifies whether it suppresses the next review, survives a move, or expires when content changes. Invalid/future dates and missing `lastWrite` also lack defined queue behavior. The current bar checks persistence, not useful review semantics.

13. **Medium — Context discovery and collapse can regress existing behavior.**  
    The promised `.cursor/rules/*.mdc` files are skipped by the referenced walker because it skips dot directories and defaults to two Markdown filenames ([plan.md:92](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:92), [registry.js:191](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/registry.js:191)). More seriously, history treats the registry as its complete inventory and removes mirrored paths missing from it ([history.js:87](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/history.js:87)). Collapsing entries must retain every physical copy in that inventory, or snapshots record existing files as deleted. Tests also omit which copy the editor opens and whether equal files at different relative scopes remain distinguishable. Existing compare is specifically wired to paired skills, not arbitrary context files ([app.js:496](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/public/app.js:496)).

14. **Medium — Cache freshness and cold-scan performance are barely specified.**  
    There is no `skill-usage` implementation in this checkout to reuse; repository search found only the plan’s reference. “Cold scan finishes” permits an arbitrarily slow or memory-heavy implementation ([plan.md:159](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:159)). A warm-speed test can pass with permanently stale results: the watcher ignores JSONL and only watches existing memory directories non-recursively ([watch.js:14](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/watch.js:14), [watch.js:63](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/watch.js:63)). No bar covers transcript append/rotation/deletion, new scopes, concurrent scans, bounded memory, or responsiveness during a cold scan.

15. **Medium — The existing real-HOME guard cannot verify the promised protection.**  
    It currently covers studio state, skill trees, and selected configuration files—**not project memories or context files** ([real-home.mjs:32](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/tests/real-home.mjs:32)). Its walker records files and symlinks but not directories, so deleting an empty directory is invisible even if the roots are expanded ([real-home.mjs:61](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/tests/real-home.mjs:61)). Running `verify.sh` twice does not establish [criterion 10](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/builds/memory-review/plan.md:162) without extending both coverage and the kinds of changes detected.
