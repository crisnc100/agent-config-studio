**Bugs**

1. **P1 — Trash metadata can destroy the payload.** Data and metadata share the same directory namespace. For a file named `trash-meta.json`, the final metadata rename replaces the original bytes, yet deletion reports success. The in-memory reproduction confirmed those bytes no longer existed. This collision also existed in the baseline and remains unfixed by the safety rewrite.

2. **P1 — Interrupted operations can falsely report successful restoration.** Accept records completion after mutation and history work. A crash in that interval leaves `done: false`; Restore excludes that step and can mark the operation restored without undoing it. Restore itself also lacks per-step progress persistence: interruption after restoring an index can make the next attempt reject that already-restored index as an outside edit.

3. **P1 — Accept can overwrite concurrent edits or follow a newly substituted directory.** The checks happen once before asynchronous history calls and earlier operation steps. The eventual rename/write uses the original pathname without another hash or containment check. The global lock only serializes Memory operations; it does not serialize external agents or existing editor routes. The external-edit overwrite was reproduced with mocked I/O.

4. **P1 — Trash restoration bypasses Memory’s containment checks.** The trash branch calls generic `restoreTrash` without `assertPlain` ([memory-ops.js:552](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/memory-ops.js:552)). Generic restore resolves the destination through symlinks using the broader allowed roots. Replacing a trashed fact’s parent directory with a symlink to another allowed directory can redirect restoration outside the original memory tree.

5. **P1 — Context IDs can return transcript text.** `readContext` accepts any target allowed by `resolveSafe`; it does not require the resolved target to be a context file ([context-map.js:102](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/context-map.js:102)). A mocked `AGENTS.md` symlink to an allowed `.jsonl` transcript produced that transcript’s sentinel text through `contextFile(id)`. Credential deny-list checks do not prevent this.

6. **P2 — Link cleanup deletes prose.** The whole-bullet deletion in criterion 2 contradicts the preservation requirement. The new test at [memory.mjs:207](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/tests/memory.mjs:207) explicitly blesses that destructive behavior.

7. **P2 — Finding eligibility is not rechecked.** Link repair validates the index’s link location but never verifies that the target remains missing or that the archive replacement remains eligible ([memory-ops.js:310](/Users/cortega/Documents/Projects/personal/agent-config-studio-wt/agent-config-studio-memory-review/lib/memory-ops.js:310)). If the missing file reappears, the old ID can still remove its now-valid link. Likewise, an old unindexed ID can append a duplicate entry.

8. **P2 — Real-home protection was narrowed.** New context files and entire newly appearing slugs are exempted without proving a live CLI created them. I compared both comparator implementations with synthetic snapshots: adding `project/.claude/skills/test/CLAUDE.md` was a failure before and only a note afterward. No existing guard A–G was weakened, but this existing check was.
