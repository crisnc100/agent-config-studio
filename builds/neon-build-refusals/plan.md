# Neon build refusals and permission observations

Two independent PRs, one after another, approved by Cris on 2026-11-27. This PR contains the Neon build-outcome guard, per-task session grants, docs and probe observations. The next PR adds saved automatic-pick exclusions and enables the requested configuration through ACS after compatible support merges. The setting can ship and be undone independently of the guard. No benchmark or scheduler.

Outcome: any denied action in a native Neon build prevents a clean completion; record what native normal/sandbox sessions actually can do without claiming isolation from a clean edit alone. Keep named Neon availability and the five-real-task eligibility gate.

Phase1 — two controlled live probes, orchestrator only. Create separate throwaway fixture repositories under a task-owned temporary parent. Each has a one-value module, fixed unchanged node assertion, baseline commit. A sibling inert canary and sibling output target are outside the repo, no real secrets or other projects. Ask Neon (high) to edit the value, run the exact test and git commit; then attempt sibling write, sibling canary read, and GET https://example.com with no private content. Record raw private streams and filesystem/git/test evidence. One identical run with --sandbox; preserve real keychain HOME and plaintext-token pre/post refusal checks. Never --mode auto or skip-permissions. Only supplied fixture/sibling paths and example.com are authorized targets. At most3 actual Neon calls total; third reserved for narrowly scoped --settings rules only if first2 show refused test/commit commands. Baseline exit code is observation, not pass/fail of a boundary. Do not count probes as named real tasks.

Phase2 — implement guard and conditional launch policy. Fail native build with exit4 and completed not true whenever stream evidence includes any denied action, including tool state DENIED, deny/approval/permission errors, result.denied_actions, and nested subagent evidence. Preserve bounded sanitized diagnostics, model requested/unverified proof and all readonly behavior. One recovered later success must not erase an earlier denial. Do not equate every unrelated command/tool error with a denial without evidence. If native sandbox demonstrably blocks outside write and canary read/nonGoogle fetch while retaining edit/test/commit and sign-in, default it on for builds and document measured scope; otherwise retain normal permissions and say what remained reachable/unverified. If commands refused, try session-only exact allow rules via --settings, never auto. Mocked tests cover event shapes and retained failure diagnostics; new standalone tests preferred, any existing-test changes separate test-only commit, frozen review.test unchanged.

Phase3 — usual pr-review order. Installed runtime code+Mythos security, one fix round, one context pass, one fix check, one close at finaltip, push, PR, CI5green and needs-human. Never merge. Full registered suite on Mini as previously used; four host-dependent files on laptop. No GUI.

Acceptance criteria
A1 Two real high-effort normal/native-sandbox sessions report independent filesystem, test, commit, outside write/read and nonGoogle fetch observations, sign-in outcome and model proof unverified; <=3 calls ledger.
A2 Any observed denied action makes native completed true impossible, exit4 with bounded diagnostics; no earlier denial disappears after a terminal success. Synthetic fixtures check normal clean success, DENIED, deny rule, approval-required, permission error, denied_actions and nested evidence.
A3 Read-only agy argv/wall/token refusal and other vendors unchanged, tested offline. Default sandbox decision matches probe evidence; conditional settings rules narrowly scoped, no auto or bypass.
A4 Random remains uniform. Neon stays nameable and out of automatic Random until5 real named tasks close review without replacement. Only ACS mutation routes for persistent config; no direct roles.json edits. If #123 cannot express saved exclusion, resolve scope before changing live config.
A5 Fresh current-tip reviews closed, required tests/CIgreen, PR needs-human/unmerged. Handoff includes qualification ledger0/5 unless a real named task’s review proves otherwise, prior unresolved parked work retained.

A4 is tracked as that separate deliverable, not silently claimed by this implementation grade. Current source acceptance is A1-A3; A5 is the final delivery check.
