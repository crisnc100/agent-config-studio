# PR D build log: review.mjs --eval

## Choices the plan left open
- **Eval marker:** `REVIEW_EVAL` (any non-blank value is eval mode) plus `REVIEW_EVAL_LOG_DIR` (absolute). The log-dir override is honoured only with the marker; without it, it is ignored with a warning. The marker without a log dir, or without `REVIEW_BASE`, stops. In eval mode these refuse: --gate, --close, --summary, --tier-json, --deferred, --fix-check, --dispute, --waive, --log-grade, --recheck-of, --log-outcome, --slices, --eval, the shadow/pick/security worker entries, --shadow-report, --pick-report, --calibrate. The check runs at module load, before --log-outcome's top-level handler.
- **Eval mode in code:** SECURITY forced to run "off", VERIFY_CMD empty, SECOND_OPINION false, startShadows/startPickShadows not called. The env set by the runner is not relied on: the child test sets REVIEW_SECURITY=always, REVIEW_SHADOW, REVIEW_VERIFY, REVIEW_VERIFY_CMD and a planted home config, and none fire.
- **Runner child env:** every `REVIEW_*` variable of the operator's shell is dropped; the child gets REVIEW_EVAL, REVIEW_EVAL_LOG_DIR, REVIEW_BASE=main, REVIEW_REVIEWER=<family>, REVIEW_PATHS=''. HOME is untouched, so model-id roles, the home config's non-eval keys (effort, claudeModel) and CLI auth are the operator's.
- **One log dir and one fresh repo per case review** (not per run): reviewContext reads the log for "already decided" findings on the same branch, and an agentic reviewer could read an earlier family's reviews/ report in a shared repo.
- **Repo build:** `git init -b main`, base tree committed on main, branch `eval-case`, `git rm -r .`, head tree, commit. Every git call has core.hooksPath=/dev/null, commit.gpgsign=false, core.autocrlf=false, a fixed identity and `--no-verify`; `add -A -f` so a case's .gitignore cannot drop files. No remote.
- **Case validation** (before the cost guard): case.json object with known keys only (id, kind, intent, expect, allow, notes); id `[A-Za-z0-9][A-Za-z0-9._-]*`; intent non-empty and not starting with `-` (it is passed as the positional intent); base/ and head/ folders of plain files (no symlink, no .git, no `.claude/review-config.json`, which would act as the temp repo's config); head differs from base; bug: non-empty expect, side head|base (default head), lines [from,to] inside that side's file; clean: no expect, allow entries on head files. Duplicate ids: every case with that id is skipped. Non-folders are skipped with "not a folder"; dot entries ignored.
- **Scoring:** reads the child's log record. A finding is located when it is not unverified-quote and resolvedPaths has its id (ambiguous paths count as unlocated). Side = head when resolvedPaths.commit equals record.head, base when it equals record.baseSha. Line ranges `a-b` use start..end. Match = same path and side, overlap with lines ±3. Bug case: caught when every expect is matched; each expect records the strongest matching finding's id and severity; the case's severity is the weakest of those. Located findings matching no expect are `extra`. Clean case: located findings inside `allow` (same ±3 window) are tolerated; outside it, `blocking()` (the real flow's rule: not filed, or unscored) are false alarms, the rest are `lows`.
- **Clean-case outcome names:** `clean` | `false-alarm` | `errored` (the plan's caught | missed | errored names bug cases).
- **Errored:** timeout, non-zero exit (message carries the stderr tail), no FINDINGS_JSON, or no matching record in the eval log. Errored repos are kept under the run's temp folder and the path is printed; scored ones are removed, and the run folder too when empty.
- **--timeout:** `15m` default; accepts `ms`, `s`, `m`, a bare number is minutes. The child runs in its own process group; on timeout the group is SIGKILLed. SIGINT/SIGTERM on the runner kills running children.
- **Cost guard:** families × valid cases × repeat; prints model calls separately when the claude team multiplies them, and a note that a missing score adds one call. Over 10 without --yes: exit 1 before any repo or call.
- **Families:** default is the reviewer role pool (CLI-filtered by loadPool). A named family resolves as the child would (claude = team per claudeModel, codex vendor, else pool / unusable / model-id). Missing CLI or an id with no CLI prefix: reported once, skipped before the guard.
- **Record:** `{type: 'eval', ts, runId, family, vendor, model, effort, modelUsed?, rubricVersion, runtimeHash (sha256 of the running review.mjs), promptHash (sha256 of reviewPrompt('') for the vendor with no intent/context/slice and base main, plus LENSES for claude), casesDir, caseIds, repeat, timeoutMs, totals, cases[]}`; model/effort come from the child records (what actually ran), falling back to the runner's resolution. Each case carries caseHash (case.json + both trees). All family records of a run are appended under the log lock at the end. `===EVAL_JSON===` prints them.

## Deviation
- **Examples live at `packs/review-gate/runtime/eval/examples/`**, not `packs/review-gate/eval/examples/`. The installer only copies the runtime folder (lib/packs.js runtimeFiles walks packs/review-gate/runtime), so only there do the examples reach an installed operator (`~/.agent-config-studio/review-gate/eval/examples/`) as templates, which is what the Bounce asked for. They are listed in the code-review part's files and pass the personal-text and model-name sweeps.
