Packs: Review gate

The card leads with what the pack does and whether it’s ready, then draws the steps: what happens, and who or what does each one. Steps you’ve turned off stay in place, dashed and marked “off”. The tabs switch between the three ways you can run it.

Review gate

/code-review Ready

A reviewer reads your branch and reports bugs. Every finding must quote real code, gets fixed once, and is logged.

How it runs
Pick per run, e.g. “/code-review premium”.
  1. Review

    Reads the branch and reports bugs. One full, careful pass. For changes where a miss is costly. Two reviews, one merged list. Bugs both found come first.

    reviewerOpus or Solpicked per review judgeFable · high reviewerOpus or Solthen judge: Fable double-checks
  2. Security pass off

    Looks only for security holes, beside the review.

    securitynot set
  3. Quote check

    Drops any finding whose quote isn’t in the code.

    script — no model
  4. Fix round

    Every high and medium is fixed, or disputed with proof.

    builderOpusthe one that wrote the branch
  5. Fix check

    One look at the fixes. No second round.

    reviewersame pick
  6. Defer and log

    What’s left is deferred and written to the review log.

    script — no model
  7. Push gate

    Refuses a push until every changed file was reviewed.

    git hook — no model

Packs: Build

Four phases, then you. The plan is attacked before any code is written, and a different model grades the result than the one that built it.

Build

/build Ready

Plans a change with you, has a builder write it, and has another model check it against what “done” means.

How it runs
  1. Understand

    Reads the code and asks what done looks like.

    your session agent
  2. Shape

    Writes the plan and the bar it must meet. Then it’s attacked.

    advisorFable · highattacks the plan (the Bounce) you approve
  3. Build

    Writes the code, one commit per phase.

    builderOpus · high
  4. Grade

    Checks the result against the bar.

    judgeFable · highAstra instead when the builder is the same vendor
  5. You judge

    Try it and decide if it ships.

    you

Small job? Lightweight mode skips the plan, the Bounce and the Grade: one builder call, then /code-review.

Packs: PR descriptions

A short flow. The note says plainly that it costs nothing extra.

PR descriptions

/pr Ready

Writes a pull request anyone can read in a minute: what changed and why, how to try it, what was reviewed.

How it runs
  1. Gather facts

    Commits, reviews and checks for the branch.

    script — no model
  2. Write it

    Plain words, in your style.

    your session agent
  3. Check it

    Makes sure the draft keeps every fact.

    script — no model
  4. Open the PR

    Posts it to GitHub.

    gh, GitHub’s tool

No extra model is called.

Models: roles

“Roles” everywhere, never “Jobs”. Each row shows who does the job and at what effort, which pack steps use it, and an Edit button. A role nobody chose says so and offers the fix.
