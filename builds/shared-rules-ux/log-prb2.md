# PR B2 log: add a rule where it is missing

Deliberate choices, server phase:

- The writer is lib/blocks-add.js, beside blocks-match.js; lib/blocks.js stays write-free. blocks.js gained `isAddTarget` and a top-level `targets` list in the GET payload (each file a rule can be added to: file, source, kind, skill, project). The list is once for all rules; the page leaves out, per rule, the files that already hold a copy. It reuses PR B's pieces: sourceFiles, resolveSafe, inPacks by real path, assertNotHardLinked, openUserFile, the proposals writer's commit, `lineStarts` (now exported from blocks-match.js).
- Targets: a listed file outside the packs that is an instruction file or a skill's SKILL.md (a skill's other .md files are not), readable, inside the roots and not a pack file by real path. A file with any copy of the rule, loose ones included, is not offered for that rule and is refused (409 "already has a copy") if named.
- Requests: preview `{ rule, files: [display path…] }`, apply `{ rule, files: [{ file, signature }…] }`; 1–200 files, no repeats, unknown fields 400 at both levels; body cap 64 KB. Each name goes through the server's own list, so a typed, absolute or traversal path is 403 and never opened. One refused file refuses the whole request.
- Placement follows the wizard's pasteBlocks byte for byte (tests compare against it): no heading → at the end, a blank line, "## Shared rules", then "\n### <name>\n\n<marker>\n<body><end marker>\n". An existing heading (level 1 or 2, the last one outside code fences): after the last end marker in its section, else after the section's last non-blank line; the section ends at the next heading of the same or a higher level. That can be mid-file, as the brief says ("after the last block under it"): bytes are inserted, never removed or changed.
- Line endings: CRLF when most of the file's line ends are CRLF, else LF. A file without a final newline gets one before the section (`newline: true` in the preview). Splicing is by bytes, so non-UTF-8 bytes are kept.
- Self-check before any preview: the new bytes must scan as the rule, marked and the same, at the expected line, and every copy the file had must still be there with the same rating, shifted by the added lines; otherwise 409 "add it by hand".
- Signature per file: sha256 over rule id, display path, the file's byte hash, the insert offset and the inserted bytes, so a changed file or a changed rule text is a 409.
- Apply order: re-locate every file and compare signatures (any mismatch: 409 naming the files, nothing written, nothing saved); then save every old file to History (any failure: 500 "Nothing was written"); then write one by one through the proposals commit (which re-checks identity and bytes with no await before each write). A failure after at least one write answers with the files written and not written, in the message and as `written` / `notWritten`.
- Preview per file: `line` (first added line in the new file), `from` and `diff` (the line before as context, the added lines, the line after when the insert is mid-file), `heading` (new | existing), `newline`, `added`, `signature`.

Then the History note, primary "Add to N files", quiet Cancel (keeps the ticks).
- A 409 shows the server's message and a secondary Preview again, which checks again first (ticks for files that left the list are dropped), then previews what is still ticked. A failure after some files were written (`written` in the body) checks again so the page shows them as they are now, with the server's message naming written and not written files.

Fix round (review 2026-11-12-16-29-29-f14ec1):

- s1: `addTargetReal` (lib/blocks.js) judges a target's kind on its real path as well as its listed name: a skill must resolve to a SKILL.md with a `skills` folder above its own folder, an instruction file to a CLAUDE.md or AGENTS.md; packs and the roots are checked there too. The GET's `targets` and the writer both use it, so a SKILL.md linking to settings.json or a notes file is neither offered nor written (403). A SKILL.md linking to another skill's SKILL.md stays a target.
- f1: the first write's commit runs a synchronous check of every file (same real path, identity and bytes as at the signature check) through the proposals writer's `recheck`, with no await before that write. A file changed during the History saves stops every write (409 naming it, "Nothing was written").
- f2: lines inside fenced code are ignored when finding the heading, the next heading and the last end marker. A file whose code fence is never closed is refused (409, "ends inside a code example… Add it by hand.").
- f3: a file the rule would push past the scan's 1 MB limit is refused at preview (413, one line).
