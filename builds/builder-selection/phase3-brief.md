# Phase 3 builder contract

## Objective
Wire the configured picker into both build skill variants once per meaningful task and document the user setting. Preserve the same chosen builder family across phases, fixes and resumes; a fresh worker is not a new pick. This is the final implementation phase for the existing task owner.

## Read first
Repo instructions and builds/builder-selection/{context,plan,advisor-report,explorer-report,log}.md, both packs/build/skills/{claude,codex}/build/SKILL.md and their existing tests. Read ~/.codex/skills/effective-agent-skills/SKILL.md before editing SKILL.md. Read docs/neon-builder.md for native dispatch, completion/error and unverified served-model limits. Inspect the actual picker packet from Phase 1, not imagined fields.

## Constraints
Make bounded edits to selection, handoff/dispatch and related docs only; do not redesign Frame/Bar/Judge or create a scheduler/cursor/workflow database. First inspect the existing plan/handoff for an owner. On an initial task, operator-named eligible builder wins; otherwise call model-id --pick builder --json once with --design only for a genuinely new frontend visual-direction decision, and task text only as needed for Jev. Frontend logic, settled design implementation, backend and database use normal strategy. Record family/effort/mode/reason/operator-named and cumulative exclusions in the existing task plan/handoff. Reuse on resume, phase and fix; retain fresh-worker boundaries. Keep the picked effort packet coherent and existing Opus medium/xhigh effort rule; store any chosen effort override. Detect an old CLI and give acs install-model-id, never guess. Preserve standing automatic quality escalation; add no permission gate. Confirm actual quota/startup unavailability before replacement, accumulate exclusions, and hand off completed commits, tests, remaining work AND partial edits. Generic failure is not proof of startup failure and may leave edits. Never silently bypass usage policy or loop forever after all candidates fail.

Dispatch according to family/model and harness: same-vendor native builder agent where available (Sol in Codex, Opus in Claude); cross-vendor CLI only where native unavailable. Neon uses ask-model --family "$BUILDER" --build --cwd canonical worktree root, native agy permissions, served model stays unverified. All builders commit phases and never push/PR/merge/review/call models. Review gets the actual recorded author. Preserve variable/capability contracts the existing tests guard (including BUILDER and EFFORT_FLAG where appropriate); do not weaken assertions just to match new prose. Do not modify installed personal skills/config or review runtime. No live provider/Jev calls, agents, reviews, push/PR/merge. Existing-test changes must be separate test-only commit describing assertions and independent check needed. Frozen review.test.mjs unchanged.

## Validation
Add meaningful runnable consumer contract tests for both variants: a forced non-first family, fresh phase/resume and fix reuse one picker result, identical family/effort through actual dispatch and review author; explicit choice, design flag, bounded cumulative replacement, old CLI and Neon route. Keep tests honest about instruction-driven behavior; do not claim a real model was exercised by stubs. Run existing build-skill contract tests and guards/registry/readme plus new tests. Do not run full suite on laptop. git diff --check. Update README and the Neon integration note only where current behavior needs explaining; preserve model strengths/negative profiles unchanged.

## Stop condition
Final implementation committed and clean, build log up to date with exact focused commands/results and test-only changes. Return concise files/commits/counts and any unresolved issue. No self-review, self-grade or push. The orchestrator runs combined code+security, one fix round, context pass, one fix check, full suite close, PR and CI, human merge only.
